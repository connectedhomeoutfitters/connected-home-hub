# app.connectedworkos.com — the application. NOTHING here should be indexed.
#
# This is not an SEO preference, it is a privacy control. The app serves customer
# estimates and invoices at token URLs (/e/:token, /i/:token) and single-use magic links
# (/portal/verify/:token, /sub/verify/:token). A crawler that fetches one of those exposes
# a customer's document — and fetching a verify link would burn it.
#
# The public marketing site is a different host (connectedworkos.com) and has its own
# robots.txt that allows everything. That is the surface meant to rank.
#
# Belt and braces: server.js also sends `X-Robots-Tag: noindex, nofollow` on every
# response here. The two controls cover different cases — this file stops the fetch, the
# header stops the indexing.

User-agent: *
Disallow: /

# ...with three deliberate exceptions, added 2026-08-18.
#
# Search Console reported "Indexed, though blocked by robots.txt". The cause is the
# interaction between the two controls above: the marketing site links to these three
# sign-in pages, so Google DISCOVERS them, but `Disallow: /` stops it fetching them — and a
# page it cannot fetch is a page whose `X-Robots-Tag: noindex` it can never read. Google
# then indexes the bare URL from the link alone.
#
# Blocking a URL therefore does NOT keep it out of the index; only the header does, and the
# header is only readable if the crawl is allowed. So these three are opened up precisely
# so Googlebot can fetch them, read the noindex, and drop them.
#
# Safe to allow: all three are public sign-in forms with no customer data, and a GET does
# nothing (the magic-link email is only sent on POST). Everything else — every token URL —
# stays disallowed, and none of those is linked from anywhere public, so nothing discovers
# them in the first place.
Allow: /login
Allow: /portal/login
Allow: /sub/login
